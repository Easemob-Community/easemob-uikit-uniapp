# 按需接入与包体积

接入 UIKit 时最常见的两个疑问：**没用到的页面会不会被打进包里？** **关掉某个功能开关能不能让包变小？** 这页把 UIKit 的产物体积拆开讲清楚，并给出「只接你需要的那部分」的做法。

## 结论先看

| 层 | 自动裁剪 | 说明 |
|---|---|---|
| 页面 | 是 | 只有宿主在 `pages.json` 里声明的页面会被编译，未声明的页面不产出 |
| 组件 | 是 | easycom 按模板标签收集；页面里没出现的组件不会进入产物 |
| `libs`（SDK 封装 / store / 领域层） | 否 | `EmKit` 与页面组件都从 `libs` 入口导入，整个模块图进包 |
| 图标字体 | 否 | 单一字体文件承载全部 420 个字形（约 115KB），与实际用几个无关 |
| 国际化词条 | 否 | 中文、英文两套完整词条同时打包 |
| `easemob-websdk` | 否 | 小程序端的处理方式见 [微信小程序 SDK 分包](./GUIDE-WEAPP-SDK-SUBPACKAGE.md) |

一句话：**「没用到的页面不打包」是自动的，「没用到的功能不打包」不是。** 减体积的杠杆在页面清单，不在配置项。

## 页面清单决定编译范围

UIKit 不在插件包里预置 `pages.json`，页面清单完全由宿主工程决定。少声明一页，那一页的整棵组件子树都不参与编译。

下表是各页面组件实际带进来的 UI 组件数量（含自身依赖；组件会在页面之间复用，所以不能简单相加）：

| 声明的页面 | 页面组件 | 编译的组件数 |
|---|---|---|
| 会话列表 | `em-conversation-page` | 16 |
| 聊天 | `em-chat-page` | 22 |
| 聊天信息 | `em-chat-info-page` | 11 |
| 通讯录 | `em-contact-page` | 6 |
| 好友列表 | `em-contact-list-page` | 13 |
| 好友申请 | `em-contact-requests-page` | 7 |
| 群组 | `em-group-page` | 13 |

几个典型组合（并集去重后的总数，全部组件共 35 个）：

| 接入组合 | 编译的组件数 |
|---|---|
| 只做会话列表 | 16 |
| 会话 + 聊天 | 27 |
| 会话 + 聊天 + 聊天信息 | 28 |
| 再加通讯录、好友列表、好友申请、群组 | 33 |

### 聊天页会带上全部消息类型

聊天页把文本、图片、语音、视频、文件、@ 提醒、置顶、快捷回复全部静态引入。因此只要声明了聊天页，这些组件都会进包——**即使你用 `inputFeatures` 把它们关掉**。当前版本无法只打包其中某几种消息类型。

## 怎么确认自己没多打包

构建完成后看产物目录，**一个组件目录 = 一个真正编译进包的组件**：

```bash
ls unpackage/dist/build/mp-weixin/uni_modules/easemob-uikit-uni/components/
```

微信开发者工具的「详情 → 本地代码 → 代码依赖分析」给出的是同一份清单。如果这里出现了你完全不打算用的页面组件，说明 `pages.json` 里还留着对应页面。

### 仓库内的诊断脚本

仓库根目录提供一个用量审计脚本，可对任意 uni-app x 工程跑一次：

```bash
node scripts/audit-usage.mjs /path/to/your-project
```

它按 `pages.json` 的编译范围给出三类结论：**直接使用**的组件、被页面组件**静态带入**的组件，以及从页面清单**不可达因而不会编译**的组件。脚本随 [GitHub 仓库](https://github.com/Easemob-Community/easemob-uikit-uniapp) 分发，不在插件包内。

## 运行时开关不改变体积

`inputFeatures`、`messageMenuKeys`、`conversationMenuKeys`、`emojiList` 等配置只影响**渲染与交互**：关掉语音入口后输入栏不再显示麦克风，但语音消息组件与相关代码仍然在包里。

想让它消失，只有两条路：

1. 不声明对应页面（页面级按需）；
2. 不用内置页面组件，改用原子组件自绘，见下节。

配置项本身的作用见 [配置参考](./CONFIG.md)。

## 只做一块嵌入 UI 时

如果只需要会话条目、头像、消息气泡这类**原子组件**，可以不经过 `libs` 入口：

- 原子组件使用深路径导入（如 `@/uni_modules/easemob-uikit-uni/components/em-conversation-item/em-conversation-item.vue`），只依赖自己用到的工具、类型与词条，不引入 store、领域层与 `EmKit`；
- 只有**页面组件**和 `EmKit` 门面会引入完整的 `libs` 模块图。

也就是说：`em-conversation-item` + 自建数据流，和 `em-conversation-page` + `EmKit`，体积差异主要来自 `libs` 与页面组件本身。选型可对照 [组件总览](./COMPONENTS.md)。

## 当前版本的边界

- **能力级按需不提供**：不能通过配置让视频消息组件、群组领域代码从产物里消失，只能通过页面清单与自绘控制。
- **图标字体与国际化始终全量**：字体是单一文件，增加/减少用到的图标不改变其大小；两种语言词条同时打包，运行时可随时切换语言。
- 如确需压缩图标字体，可在自己的工程里对 `em-icon` 的样式做子集化替换；这属于工程侧定制，插件升级覆盖 `uni_modules` 后需要重新处理。
